# 0.14 — Capture pipeline reliability

**Theme:** the background workers. Everything here is about a job that takes 90
seconds and then fails silently.

**Rationale:** a voice memo takes transcription plus enrichment plus vault sync.
Today that is one opaque background task with no progress, no retry and no way
to cancel. Long jobs need lanes, retries and a dead-letter list — otherwise every
other bundle inherits silent failures.

**Depends on:** 0.3 (`capture_id`, pipeline stepper UI).
**Blocks:** 0.15 (chaptered video summaries reuse chunking), 0.9 (#106
scheduled jobs reuse the scheduler).

## Backend

The pipeline in `services/process.py` becomes an explicit job table, not an
inline `asyncio.create_task`. One worker pool, priority lanes, per-stage state.

```sql
ALTER TABLE notes ADD COLUMN stage TEXT NOT NULL DEFAULT 'queued';
ALTER TABLE notes ADD COLUMN stage_timing TEXT;   -- JSON: {transcribe_ms, enrich_ms, sync_ms}
ALTER TABLE notes ADD COLUMN attempts INTEGER NOT NULL DEFAULT 0;
ALTER TABLE notes ADD COLUMN last_error TEXT;
ALTER TABLE notes ADD COLUMN priority INTEGER NOT NULL DEFAULT 0;
CREATE INDEX idx_notes_stage ON notes(stage, priority);
```

`#332` idempotency keys the table; a retry of the same `capture_id` updates the
existing row rather than inserting.
