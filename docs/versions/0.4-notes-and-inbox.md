# 0.4 — Notes, Inbox & organisation

**Theme:** what happens to a note after it lands. Filing, editing, linking,
protecting.

**Rationale:** the Inbox is where the app is judged. This bundle gives notes a
type, a lifecycle (pinned / archived / trashed) and the link structure that
0.6 search, 0.10 vault sync and 0.15 wikilinks all read from.

**Depends on:** 0.3 (`notes.type`, `capture_id`). **Blocks:** 0.6, 0.10, 0.15.

## Data model

```sql
ALTER TABLE notes ADD COLUMN starred INTEGER NOT NULL DEFAULT 0;
ALTER TABLE notes ADD COLUMN trashed_at TEXT;          -- #274 soft delete
ALTER TABLE notes ADD COLUMN color TEXT;               -- #25
ALTER TABLE notes ADD COLUMN fields TEXT;              -- #471 typed custom fields, JSON
ALTER TABLE notes ADD COLUMN sensitive INTEGER NOT NULL DEFAULT 0;  -- #26
ALTER TABLE notes ADD COLUMN raw_text TEXT;            -- #19/#21 pre-clean text
ALTER TABLE notes ADD COLUMN review_state TEXT NOT NULL DEFAULT 'enriched'; -- #474
CREATE INDEX idx_notes_trashed ON notes(trashed_at);
CREATE INDEX idx_notes_starred ON notes(starred);
```

Wikilinks (#22) live in a link table, not a regex at query time:

```sql
CREATE TABLE note_links (
  src TEXT NOT NULL, dst TEXT NOT NULL,
  PRIMARY KEY (src, dst)
) WITHOUT ROWID;
```
