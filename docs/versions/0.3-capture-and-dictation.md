# 0.3 — Capture & dictation ergonomics

**Theme:** everything that puts an idea *into* the app, and the 20 seconds after.

**Rationale:** capture is the front door. Every later bundle assumes captures
arrive with a type, tags, an undo window and a visible processing state. Doing
this first makes the data model (`note.type`, `capture_id`, `source`) land once
instead of being retrofitted by 0.4 and 0.14.

**Depends on:** nothing. **Blocks:** 0.4, 0.14.

## Data model

```sql
ALTER TABLE notes ADD COLUMN type TEXT NOT NULL DEFAULT 'text';  -- idea, bug, quote, shopping, meeting
ALTER TABLE notes ADD COLUMN capture_id TEXT UNIQUE;              -- #332 idempotency, do it now
ALTER TABLE notes ADD COLUMN source TEXT;                         -- clipboard, screenshot, email, extension
ALTER TABLE notes ADD COLUMN source_title TEXT;                   -- #3 window title of origin
CREATE INDEX idx_notes_type ON notes(type);
```

Templates (#1) are a small JSON blob in config, not a table:

```toml
[template.idea]
tags = ["idea"]
prompt = "Summarise as an idea worth revisiting. Suggest 3 tags."
```

  command grammar needs a design, not a regex.
