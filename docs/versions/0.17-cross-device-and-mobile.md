# 0.17 — Cross-device, mobile & sync

**Theme:** capture from the phone, read on the LAN, sync between your own
machines.

**Rationale:** this is the highest-risk bundle and the least "local-first". Do it
last of the feature work. Everything it needs already exists as a read-only API;
what it adds is auth, pairing and conflict handling.

**Depends on:** 0.11 (token auth, encryption), 0.14 (job table for drained
inboxes). **Blocks:** nothing.

## Design decisions to make first

1. **Sync engine.** No new dependency unless one earns itself. A file-based
   append-only log under `~/.local/share/fleeting/sync/` plus `#224` folder sync
   covers "my own machines" without a CRDT library. Revisit only if two devices
   edit the same note offline in the same hour.
2. **Trust model.** Pairing code → long-lived device token, revocable per device,
   listed in #140's audit log.
3. **Read-only is the default.** The LAN web view (#220) is read-only. Only the
   capture endpoint accepts writes.

  single-user local app; revisit only with a real reason.
