# 0.16 — Proactivity, notifications & habits

**Theme:** the app noticing things before you ask, and being honest about when
it should shut up.

**Rationale:** everything so far is pull. This is push: reminders, nudges,
check-ins, a notification centre. Push features fail by being annoying, so the
bundle is deliberately weighted toward *control* (quiet hours, per-source
switches, a centre that shows everything) rather than toward more nudges.

**Depends on:** 0.14 (one scheduler), 0.5 (tasks and streaks).
**Blocks:** 0.17 (the phone needs the same notification discipline).

## Data model

```sql
CREATE TABLE notifications (id TEXT PRIMARY KEY, at TEXT, kind TEXT, title TEXT,
  body TEXT, read_at TEXT, action TEXT);
CREATE TABLE checkins (day TEXT PRIMARY KEY, mood INTEGER, energy INTEGER, note_id TEXT);
CREATE TABLE habits (id TEXT PRIMARY KEY, name TEXT, target_days TEXT);
CREATE TABLE habit_log (habit_id TEXT, day TEXT, done INTEGER, PRIMARY KEY (habit_id, day));
```

`notifications.py` already exists and posts to the desktop notifier. This
bundle makes it a table first, a notifier second — so a missed notification is
visible in the app instead of lost.
