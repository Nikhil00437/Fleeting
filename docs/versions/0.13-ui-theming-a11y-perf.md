# 0.13 — UI polish, theming, a11y, i18n & performance

**Theme:** the app stops looking like a prototype and starts holding up at 100k
notes.

**Rationale:** grouped because they share one mechanism — a design-token layer
plus virtualised lists. Themes without tokens are per-view CSS edits; density,
text size, reduced motion and dark/light are all token switches. Virtualised
lists are the precondition for #252, #479 and #480.

**Depends on:** 0.8 (chart components to theme). **Blocks:** nothing.

## Foundation: tokens

```css
/* index.css — one source of truth, every view reads these */
--bg, --surface, --ink, --ink-muted, --accent, --line
--density-row: 1.75rem | 2.5rem;          /* #76 */
--text-scale: 0.875 | 1 | 1.125;           /* #86, #176 */
--dur: 0ms | 1ms;                          /* #81, set from prefers-reduced-motion */
```

## Deferred, on purpose

- #177 UI translations (Hindi, Spanish) — only after the token layer makes
  strings extractable. Do the extraction here; ship the locales when they exist.
- #243 an interactive tour and #365 animated micro-illustrations — polish on
  polish. Nice, not load-bearing.
- #484 an ANN index past a vector-count threshold — measure first. 100k notes
  (#479) may not need it.
- #481 FTS tuning and #183 DB maintenance — Settings tools, small; they belong to
  whichever release next touches the settings tabs.
